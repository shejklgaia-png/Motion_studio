# Motion Studio アーキテクチャ

## 評価パイプライン

キーフレームFKのサンプリング → 関節制約 → IK → IK結果の制約再確認 → 3D描画・接触検証 → ベイク

FK基準姿勢は `frames` に保持し、IKと制約は原本を上書きせずに評価します。

## モード設計

- モーション: キーフレーム、位置、回転、スケール、タイムライン
- IK: チェーン、手法、目標、適用区間
- 制約: ローカル軸位置・回転・スケールの上限・下限
- 接触: 静的テスト物体と接触センサー
- 診断: 原本姿勢、IK残差、接触警告
- 書き出し: JSON保存・復元、Godotアニメーションベイク

## 書き出し後の品質検査

`MotionEngine.export_animation_tres()` は `ResourceSaver` による保存後、`ResourceLoader` で `.tres` を再読込して `MotionExportAudit.audit_export()` に渡します。キーフレーム時刻のローカルTransformは厳格に検証し、キー間の補間誤差は別の指標として警告表示します。失敗した照合を出力失敗と混同しません。レポートは最後の出力に属し、プロジェクトには保存しません。

この検査は元の `MotionRig` の親子階層を前提としています。外部シーンの異なるアニメーションルート、Skeleton3D、リターゲティングの完全な再現性検査は次段階です。
